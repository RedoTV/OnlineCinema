# Тестирование и демо-данные

Дипломный проект руками проверяется так, без .http файлов.

## Демо-данные (JS-скрипт поверх API)

Каталог наполняет сейчас **Node-скрипт**, который стучится в публичный API
(никак не трогая логику бэкенда). Идемпотентен: повторный запуск не дублирует,
а лишь дочищает то, чего не хватает (биографии/портреты, сезоны/серии,
публикацию статей и т.п.).

```bash
node scripts/seed-data.mjs http://localhost:5000/api
```

Полезные ключи: `--dry-run` (показать план без записи), `--users=N`, `--no-publish`.
По умолчанию входит админом `admin1@onlinecinema.com` / `AdminPassword123!`
(переопределить можно `--admin-email=`/`--admin-pass=`).

Контент задан в `scripts/seed-content.mjs`: жанры, актёры (с биографиями и
портретами), фильмы, сериалы с настоящими названиями серий, статьи.

> Рекомендуемый прогон на чистой базе: выключить встроенный сид
> (`SEED_DEMO_DATA=false` в `.env`), поднять compose и запустить скрипт один раз.
> Если база уже старая (со старым демо-контентом) — снести её
> `docker compose down -v` и поднять заново.

## (Старый путь) C#-сид внутри бэкенда

`SEED_DEMO_DATA=true` в `.env` по-прежнему запускает встроенный сид
(`src/OnlineCinema.Backend/Services/Seeding/DemoSeeder.cs`) на пустой базе.
Но рекомендуется использовать JS-скрипт выше как единый источник каталога.

## Смоук-тест API

Ставит весь критичный путь: рега -> логин -> каталог -> сериалы ->
оценка/статус -> комменты/лайки -> статистика. Отдаёт понятный ититог.

```bash
# все контейнеры подняты, каталок отдельным флагом
node scripts/smoke-test.mjs http://localhost:5000/api
```

Нужен Node 18+ (глобальный fetch, никаких зависимостей).
Код: `scripts/smoke-test.mjs`.

## Postman

`docs/postman/OnlineCinema.postman_collection.json` — импортируй в Postman.
Задай переменные `base_url` и `token`. Токен сам подставляется скриптом
на коллекции после Register/Login (автовиждет в environment).
